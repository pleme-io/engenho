# engenho M0.1 — runnable single-node cluster (execution checklist)

Dependency- and leverage-ordered path to **a single-node engenho you can
`kubectl apply` a Deployment to and watch the Pod run.** Derived from the
2026-06-06 critical-path audit of all 7 subsystems (see `M0-ROADMAP.md` for the
phase framing). Each item is a bounded, individually `cargo test`-gated unit;
land each green + adversarially verified before the next.

**Destination (Operating Principle #0):** `Put Deployment → ReplicaSet → Pod
chain converges → scheduler binds to a fitting node → kubelet starts the
container`, with a revision-coherent WATCH the whole way (the feature "where
every k8s clone dies"). Everything below the binary-assembly line is the path
down to that destination.

## Status — M0.1 COMPLETE (all 10 items ✅)
Critical path `1 → 2 → 3 → 4 → 6 → 7` **and** enhancements `5, 8, 9, 10` are all
done, each adversarially verified + pushed. **engenho is a runnable single-node
cluster:** a POSTed apps/v1 Deployment converges to a running container in one
process (proven by `m0_1_single_node_convergence.rs`), with status subresources,
optimistic concurrency, pagination, group routing/discovery, kubelet pod-lifecycle
management, and resource-fit scheduling. Boots on a **FakeBackend** kubelet (no
real containers) with **no networking** — those are M0.2+.

## M0.2 — engenho runs REAL containers via PodmanBackend ✅
The kubelet's `PodmanBackend` now reliably materializes ACTUAL `podman`
containers on the host (the FakeBackend was M0.1's stand-in). Landed in
`engenho-kubelet/src/backend.rs`:
- **Pure typed argv builders** — `run_argv`/`inspect_argv`/`stop_argv`/`rm_argv`
  emit the exact `podman` argv AFTER the binary, so the `ContainerSpec → podman`
  mapping is unit-testable without spawning a process (the inline-against-a-live-
  `Command` mapping is gone). A pure `parse_inspect(id, text) → ContainerStatus`
  extracts the `Running|ExitCode|IPAddress` parser too. 17 new lib unit tests.
- **Typed `PullPolicy { Never | Missing | IfNotPresent }`** (default `Never`,
  maps to `--pull never`) — every `podman run` carries an explicit `--pull` flag
  so the backend never falls back to podman's ambient policy (which would contact
  a registry through a possibly-broken credential helper). `Never` is the M0.2
  default since the e2e image (busybox) is pre-cached; the field keeps the path
  extensible without a second code path.
- **`REGISTRY_AUTH_FILE`** — the backend NEVER hardcodes an auth path. By default
  it inherits the spawned process env (tokio `Command` inherits the parent env;
  no `env_clear`), so an operator/test that exports `REGISTRY_AUTH_FILE` pointing
  at a valid (possibly empty `{"auths":{}}`) authfile bypasses the broken machine
  credential helper. Optional typed `registry_auth_file: Option<PathBuf>` override
  sets it explicitly for deterministic tests.
- **Name-conflict surfacing** — a podman `run` that fails because a leftover
  container (`<namespace>_<pod>`, deterministically built by the kubelet) already
  exists is mapped to a recognizable typed `KubeletError::Backend` (stderr
  "already in use") rather than an opaque failure. Adopt-existing-by-name is a
  future item; the deterministic name makes by-name status/stop/remove possible.

Runtime selection is unchanged structurally: `RuntimeConfig.kubelet_backend =
Podman` already routes `build_backend → make_container_runtime → PodmanBackend`
(`PodmanBackend::new()` = pull `Never` + inherit `REGISTRY_AUTH_FILE`), so config
stays minimal.

**Load-bearing proof** `engenho-runtime/tests/m0_2_real_container.rs` (ignore-gated,
run via `cargo test -p engenho-runtime --test m0_2_real_container -- --ignored`):
POST a busybox `sleep 300` Deployment over real HTTP → the chain converges → a
REAL `podman` container named `default_<pod>` reports Running (cross-checked
against the Pod's HTTP `status.phase=Running`/`Ready=True`), then DELETE the
workload over HTTP → poll until podman shows NO such container (the kubelet's
`stop`-then-`remove` ran on the real backend). A `Drop`-guard force-removes the
container on ANY exit so a failed run leaves no orphan. The test runs on a
multi-thread tokio runtime so its blocking podman polls don't starve the driver
tasks. Boots via `Runtime::start` with `kubelet_backend = Podman` so it exercises
the config-selection mechanism itself.

## What's next (M0.3+, from `M0-ROADMAP.md`)
- **Real CRI** — a containerd/CRI client backend alongside PodmanBackend (the
  conformance-grade runtime path; podman is the local-dev path M0.2 ships).
- **Networking** — CNI / DNS / kube-proxy / local-path provisioner / cluster CA (the largest greenfield).
- **Datastore depth** — etcd-v3 gRPC wire, true MVCC snapshot reads (the pagination interim's destination), compaction.
- **Apiserver depth** — authn, full RBAC enforcement, real admission webhooks, SSA/SMP.
- **Multi-node** — revoada distribution (iroh R5 + apiserver bridge) → HA, the surpass-k3s axis.
- **Conformance** — CNCF Certified Kubernetes (v1.34, zero skips) is the M4 ship gate.
