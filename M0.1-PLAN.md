# engenho M0.1 — runnable single-node cluster (execution checklist)

Dependency- and leverage-ordered path to **a single-node engenho you can
`kubectl apply` a Deployment to and watch the Pod run.** Derived from the
2026-06-06 critical-path audit of all 7 subsystems (see `M0-ROADMAP.md` for the
phase framing). Each item is a bounded, individually `cargo test`-gated unit;
land each green + adversarially verified before the next.

**Destination (Operating Principle #0):** `Put Deployment → ReplicaSet → Pod
chain converges → scheduler binds to a fitting node → kubelet starts the
container`, with a revision-coherent WATCH the whole way (the feature "where
every k8s clone dies"). Everything below the binary-assembly line is the path
down to that destination.

## Critical path to "runnable"
`1 (✅) → 2 (✅) → 3 (✅) → 4 (✅) → 6 (✅) → 7 (✅)` — **complete: engenho is now a
runnable single-node cluster.** A POSTed apps/v1 Deployment converges to a running
container in one process (proven by `m0_1_single_node_convergence.rs`). Items 8, 9, 10
are parallelizable enhancements that real workloads need but that don't block first-boot.

## Honest scope
This is M0.1 — one milestone. A fully-featured, CNCF-conformant engenho remains
the multi-quarter program in `M0-ROADMAP.md` (datastore → apiserver → controllers
→ kubelet → networking → revoada multi-node → conformance). M0.1 = the point where
engenho stops being a library and becomes a cluster.
